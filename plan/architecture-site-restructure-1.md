# Introduction

![Status: In progress](https://img.shields.io/badge/status-In%20progress-yellow)

> **Progress:** Phases 1–4 complete (teardown · the four-layer reorganization with vitest and CI · the i18n foundation: page registry, next-intl locale routing, Payload localization, metadata/hreflang · the CMS restructure: "A Clínica" + one global per page, reshaped collections, the destructive migration). Phase 5 (shared chrome and design primitives) is next.

This is the **master plan** for rebuilding the Símbolos do Self website as the experience defined in `CONCEPT.md` v3. The currently built site (home sections, `/blog`, `/simbolos`) predates the concept and is replaced, not migrated. The site is unreleased: all changes are big-bang on a branch with Vercel previews; destructive CMS migrations are authorized (content exported to a reference document first).

This plan owns everything cross-cutting: content export and teardown, the **layered-architecture reorganization** (Phase 2, per the `frontend:layered-frontend-architecture` skill), the i18n foundation (pt-BR canonical at root + full `/en/*` English mirror), the CMS reorganization (one global per page + one cross-page "A Clínica" global), the shared chrome and design primitives, the being-found/AEO package, and verification. The eight pages themselves are built in Phase 6, each via a **dedicated per-page plan** (`plan/feature-page-<key>-1.md`, authored just-in-time) wrapping an `impeccable` **shape** run.

Decisions locked with the owner on 2026-08-04 (recorded in CONCEPT.md §6/§9/§14): bilingual from launch with browser-language greeting and a typographic PT·EN header toggle (no flags); browser-side language persistence only; EN copy translated by the dev from her pt-BR source, polished later; blog and `/simbolos` removed; fee via CMS with "a combinar" fallback; wheel visual-only; site-wide labeled-placeholder policy for missing assets; greenlit touches = A Lâmina, O selo, O quadro inteiro, Sonho ampliado, moon colophon; O céu desta noite and the live Instagram feed are follow-up plans. Also locked 2026-08-04: adopt the four-layer architecture (`infrastructure → domain → view → app-as-routes`); retire `scripts/arch-check.sh` (deleted); CI runs automated checks (typecheck · lint · tests) only — note that **no CI existed before this plan**: there was no `.github/` directory and the husky pre-commit ran an unconfigured (no-op) lint-staged. Amended same session: cookieless aggregate analytics are **in** (SEC-001); the Instagram section's presentation format stays open until its shape run (REQ-010); tooling upgrades are authorized to fix the local build OOM (CON-004, TASK-053).

## 1. Requirements & Constraints

- **REQ-001**: The eight-page map of CONCEPT §6: `/`, `/analise`, `/orientacao-profissional`, `/sobre`, `/primeira-conversa`, `/perguntas`, `/internacional`, `/privacidade`. Every navigation surface (header, footer, sitemap, llms.txt, hreflang) derives from one canonical page registry in `src/domain/site/pages.ts`.
- **REQ-002**: Full bilingual site. pt-BR at the root, canonical; English mirror at `/en/*` with translated slugs (`/en`, `/en/analysis`, `/en/career-guidance`, `/en/about`, `/en/first-conversation`, `/en/questions`, `/en/international`, `/en/privacy`) — translated rather than shared slugs: keyword-bearing URLs for the EN queries and native reading for anglophones; the registry owns the pt↔en mapping so the cost is one table. hreflang + `x-default` on every page. First visit negotiates locale from `Accept-Language`; the header PT·EN toggle (typographic, never a flag) switches; preference persists in a browser cookie only.
- **REQ-003**: CMS reorganized for Luiza: one Payload global per page with tabs matching the page's CONCEPT sections, plus one **A Clínica** global holding every cross-page fact exactly once (identity, CRP, WhatsApp `+55 11 96415-8128`, email, positioning sentence, availability state, response window, fees, bilhete openers, Jung passage pool). All admin labels/descriptions in pt-BR. All visitor-facing text fields `localized: true`.
- **REQ-004**: North star is WhatsApp conversations started. CTAs are in-flow only — never sticky buttons, never floating bubbles. The bilhete openers are worded per origin (attribution in her voice, zero visitor tracking).
- **REQ-005**: Placeholder policy (CONCEPT §11): any missing asset renders as a quiet labeled frame (`MediaPlaceholder` component) describing what belongs there. The current selfie comes down.
- **REQ-006**: Fee fields optional; frontend renders "a combinar" (pt) / "discussed in the first conversation" (en) when unset. Currency policy per CONCEPT §8.9 (BRL on pt pages; USD/EUR framing on `/internacional` and `/en/*`; never automatic conversion).
- **REQ-007**: The mandala wheel on `/analise` is visual-only; CMS fields for her readings exist but render nothing until filled.
- **REQ-008**: Greenlit creative touches ship at launch: A Lâmina (mobile Cosmos substitute), O selo (bilhete seal, <600 ms, never blocks the WhatsApp handoff), O quadro inteiro (un-cropping Instagram tiles), Sonho ampliado (structure with placeholders until her words exist), moon colophon (discrete, in the footer colophon).
- **REQ-009**: The Cosmos stays (protected feature) and exposes a data interface (star field positions/config as input) so "O céu desta noite" can drive it later without a rewrite.
- **REQ-010**: The home carries an Instagram bridge section — the commitment is _her feed present and alive on the site_, not a specific widget: the presentation format (tile carousel, grid, single featured post…) is decided during the Início shape run. It ships with labeled placeholder tiles simulating the chosen behavior (including the un-crop interaction where tiles are used); the live Graph API feed is a follow-up plan gated on her Meta connection. Deferred idea noted for that follow-up: echo the latest post's color palette in on-screen accents — palette extraction is deterministic (color quantization, no AI API needed), but any _generated_ shapes/ink-drops would collide with CONCEPT's banned-ornament rule, so a compliant version tints only sanctioned ornament (the mark, plate-detail crops).
- **REQ-011**: Being-found package: JSON-LD entity graph via the single `jsonLd` module (`src/view/seo/jsonLd.tsx` after Phase 2 — never bypassed) — organization (online-only, no street address) + person (credentials, alumniOf, languages pt/en) + the two services + `sameAs` → Instagram; title pattern `<página> · Símbolos do Self`; markdown twins of all content pages in both locales; regenerated `/llms.txt`; social share card from the plate system, ready before announcement.
- **REQ-012**: Every page front-loads who/what/for-whom/how-to-reach in its first screen of content (AEO), in both locales.
- **REQ-013**: CI (new GitHub Actions workflow) runs automated checks only: typecheck, lint, unit tests. No architecture-enforcement scripts. Build validation happens on Vercel previews. The pre-commit hook gets a real lint-staged config (format + lint staged files) or is removed.
- **SEC-001**: Measurement is aggregate and cookieless (owner decision 2026-08-04). **Vercel Web Analytics is enabled** — visits, paths, referrers, countries: the signal for whether international targeting works — with no analytics cookies, no visitor identification, and therefore no consent banner (a banner would violate the no-popups rule). No forms, chatbots, popups, or personalisation; the only cookie is the locale preference; `/privacidade` names both the cookie and the aggregate stats honestly.
- **SEC-002**: Testimonials are consent-gated structurally: the query/render path excludes records without a recorded consent flag; section hides at zero.
- **CON-001**: Online-only — no page, image, or metadata may claim in-person practice.
- **CON-002**: English register rule: "clinical psychologist working in the Jungian tradition", never "Jungian analyst". Her pt-BR supplied text is the source copy; EN is translated from it (owner: dev), polish deferred.
- **CON-003**: Layered architecture per the `frontend:layered-frontend-architecture` skill: `src/infrastructure/` (Payload local-API accessors, browser storage — no rules, no React) → `src/domain/` (types, rules, transitions — no React/Next, no URLs) → `src/view/` (React, feature-first — never raw Payload shapes) → `src/app/` (thin routes: fetch via domain action → serialize → render view page). Payload schema lives in `src/payload/` outside the frontend layers. No barrel files; named exports; one concept per file. Enforced by the skill's review checklist + colocated domain tests — **not** by a script (`scripts/arch-check.sh` deleted 2026-08-04).
- **CON-004**: Local tooling limits. `pnpm build` OOMed when this plan was written; as of TASK-053 (2026-08-04) it completes again, but at ~3.5 GB peak RSS it stays sensitive to what else holds RAM — when it dies, fall back to `tsc` + `next dev` + the Vercel preview build rather than tuning heap flags (Turbopack's native memory ignores `--max-old-space-size`). Lint needs `--threads=2`, now baked into the `lint` script. WebGL performance is verified on real hardware/preview, not via the software-WebGL MCP browser.
- **CON-005**: Prod DB is on Luiza's Neon account (not reachable via local neonctl); schema changes deploy through Vercel. Destructive migration approved; export content first (Phase 1).
- **CON-006**: WON'T list (CONCEPT §12): no blog, no dark mode, no booking calendar, no urgency mechanics, no zodiac imagery on the orientação page, no flags/dropdowns for language, no AI decoration outside the Cosmos carve-out.
- **CON-007**: WCAG 2.1 AA; reduced-motion alternative for every animation; LCP < 2.5 s on 4G; mobile-first.
- **GUD-001**: Plates are the only saturation on screen; UI follows the 60-30-10 pigment rule; all-serif (Cardo display + Vollkorn body); small-caps = world voice, prose/italics = Luiza's voice; operational facts never in decorative small type.
- **GUD-002**: All visitor-facing copy lives in the CMS — never hardcoded — because copy will be polished later without code changes.
- **PAT-001**: Per-page build ritual (Phase 6): author `plan/feature-page-<key>-1.md` → run `impeccable` shape for the page → implement → run impeccable finish-review → verify checklist (both locales, markdown twin, JSON-LD, AEO front-load, reduced-motion, placeholders labeled).
- **PAT-002**: Every page carries at least one plate (placeholder allowed) and at most one wow set-piece.
- **PAT-003**: Vertical slice adapted to RSC + Payload: `infrastructure/payload/` accessor (Payload local API, one function per global/collection query) → `domain/<concept>/` action normalizes to app types → server-component route fetches and passes props → `view/` renders; client components only for interactive islands (Cosmos, toggle, selo, un-crop). New pure domain logic gets a colocated `*.test.ts`.

## 3. Alternatives

- **ALT-001**: One giant plan covering all pages — rejected: shape runs are page-scoped and interactive; a single plan exceeds executable session scope and goes stale by Phase 6.
- **ALT-002**: Pages-as-collection with layout blocks — rejected: the concept's pages are fixed compositions; block builders let the editor break layouts and make the admin harder, defeating the simplification goal.
- **ALT-003**: Geo-IP language detection — rejected: a Brazilian in London must land on Portuguese; browser language is the correct signal for exactly the audiences ranked in PRODUCT.md. Accept-Language negotiation + cookie chosen instead.
- **ALT-004**: Flag icons for the language toggle — rejected with owner agreement: flags map to countries, not languages, and CONCEPT bans them; typographic PT·EN chosen.
- **ALT-005**: Incremental page-by-page rollout on prod — rejected: site is unreleased; a hybrid old/new nav fails the "where am I?" test for weeks with no benefit.
- **ALT-006**: Launch pt-only and defer EN (original CONCEPT v2 position) — overruled by owner on 2026-08-04: being welcoming to international clients is essential from day one.
- **ALT-007**: Keep the `core/lib/ui` layout with `arch-check.sh` — rejected by owner 2026-08-04: adopting the `frontend:layered-frontend-architecture` four-layer layout instead; grep-based enforcement replaced by the skill's review checklist + colocated domain tests.
- **ALT-008**: Enforce layer boundaries in CI with a dependency-graph tool (eslint-boundaries / dependency-cruiser) — rejected: owner wants CI minimal (automated tests and the like only); review + tests suffice at this codebase size.
- **ALT-009**: Reorganize architecture after the rebuild instead of before — rejected: every phase after 2 creates files; doing the reorg first means new code is born in the right layer instead of being moved twice.

- **RISK-007**: The Phase 2 move is a large mechanical diff that could smuggle in behavior changes — mitigated: moves and renames only, no logic edits in the same commits; `tsc` + tests + `next dev` smoke check gate it.
- **RISK-008**: Without a mechanical layer check, boundary drift is possible — accepted by owner (ALT-008); the skill's review checklist runs on every diff, and TEST-011's grep catches old-alias regressions.
